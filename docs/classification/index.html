A Classification Pipeline

Build a pipeline that predicts a category (e.g., will this incident report escalate, or which species an observation records) from its features, and judge it with a confusion matrix and the right metric. A distinct kind of analysis: predictive modeling with a categorical outcome.

  • Classification predicts a label, not a number.
  • A confusion matrix shows the kinds of errors a classifier makes.
  • Accuracy alone misleads when classes are imbalanced.
  • The right metric depends on the cost of each kind of error.

12.1 A synthetic incident table

  • We predict whether a disaster incident escalates from two features: its severity and its kind.
  • The ecology twin predicts species from an observation’s mass and length; the same code runs with the columns renamed.
  • Start by pinning the seed, then generate rows.
  • random.seed makes the generator reproducible: the same seed gives the same rows every run, so a colleague can re-run and check the whole pipeline.
  • escalated is the label we will predict: 1 means the incident escalates, 0 means it does not.
  • The chance of escalation rises sharply with severity, and fires escalate more often than power outages, so there is a real signal for a model to find.
  • The label is imbalanced: most incidents do not escalate.

12.2 Split and fit

  • Fit on one part of the data and evaluate on the rest, so the score reflects how the model does on rows it has not seen.
  • The rows are already in random order, so the first 80% and last 20% form a fair split.
  • Our classifier is a threshold rule: predict escalation when severity is at least some cutoff.
  • It is crude but transparent, and a real pipeline often starts with a simple rule before reaching for something fancier.
  • To fit the rule, try each cutoff on the training data and keep the one that best balances precision and recall.
  • First we need to count the four kinds of outcomes, and turn those counts into scores.
  • A true positive is an escalation we caught; a true negative is a non-escalation we correctly ignored.
  • A false positive is a false alarm; a false negative is an escalation we missed.
  • Precision is the fraction of our alarms that were real; recall is the fraction of real escalations we caught.
  • F1 is their harmonic mean, a single number that rewards both at once.

12.3 Predict and evaluate

  • Apply the chosen threshold to the test data, which the fit never saw.
  • The matrix has four cells: true negatives top left, false positives top right, false negatives bottom left, true positives bottom right.
  • The diagonal is correct answers; the off-diagonal is two different kinds of mistake.

12.4 Why accuracy alone misleads

  • Accuracy is the fraction of rows we got right, but on imbalanced data a trivial rule can score well.
  • A classifier that always says “no escalation” gets every non-escalation right and only misses the rare escalations.

  • With about a third of incidents escalating, “always no” is right roughly two times in three, yet it catches none of the escalations.

  • Its accuracy is just the share of the majority class, which is why the number alone is deceptive.

  • Accuracy hides that failure; recall exposes it.

  • Which metric matters depends on the cost of each kind of error.

  • If a missed escalation costs lives, prefer high recall: we would rather send some false alarms than miss one real escalation.

  • If every alarm sends a crew and crews are scarce, prefer high precision: we would rather miss an occasional escalation than waste a crew.

  • There is no single best metric; there is a metric that matches the decision the model feeds.

  • The ecology twin is the same shape: predict species from mass_g and length_mm, and judge the result with the same confusion matrix.

  • Rename the label, swap the feature columns, and the pipeline runs unchanged.
