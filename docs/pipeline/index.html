Your First Pipeline

Build a small end-to-end exploratory pipeline over incident records: generate a sample, ingest it, clean the obvious problems, summarize it (incidents per kind, severity distribution), and plot the result. Along the way, meet the two tools this course leans on for exploratory work: Polars for dataframes and Vega-Altair for charts.

  • A pipeline is ingest → clean → explore → summarize → communicate.
  • Each stage is a small, checkable step; the next stage trusts the last.
  • The ecology twin has the same shape: observations per species instead of incidents per kind.

3.1 Make a sample

  • A fixed seed makes the pseudo-random sequence reproducible, so this lesson runs the same every time and the numbers below can be checked against the output.
  • Generate the sample inline so the lesson is self-contained; a real pipeline would read this from a file or an API instead.
  • The coordinate ranges pin the incidents to south-eastern Australia, the same region the full generator uses; that is an assumption written down rather than hidden in the code.

3.2 Ingest

  • Ingest brings raw records into a dataframe. Here we round-trip through CSV so read_csv is the ingest step; an API or a database would substitute for the file.
  • head shows the first rows; the schema it prints is the contract the rest of the pipeline relies on.

3.3 Clean

  • Cleaning is its own lesson; this synthetic data has little to fix, so profile first: check the types and count missing values.
  • The one real clean-up is parsing timestamp from a string into a datetime, so ordering and date arithmetic work later.

3.4 Explore

  • select picks columns; filter picks rows. Both return a new frame and leave the original untouched.
  • high.shape is the number of rows and columns: the filter keeps only the most severe incidents.

3.5 Summarize

  • group_by plus an aggregation collapses many rows into one row per group.
  • Count per kind is the headline number: which incident type is most common?
  • The severity distribution is the same operation on a different column.

3.6 Reshape

  • pivot spreads one column’s values across the columns, turning a long table into a wide one. Here the severity counts become a matrix with one row per kind.
  • A null cell means no incident of that kind had that severity; the row and column totals are the summaries computed above.

3.7 Communicate

  • Altair turns a summarized frame into a chart with one declaration: encode the x and y channels and the notebook renders it.
  • kind is nominal (N) so each value is a separate bar; len is quantitative (Q) so bar height is a measured value. sort="-y" orders the bars tallest first.

3.8 Check the answer

  • Every pipeline ends by checking its answer against something known. The synthetic data gives us ground truth: the counts must sum to the number of rows, and every kind must appear.
  • The ecology twin runs the same stages with observations grouped by species, so “count per kind” becomes “count per species” and the chart labels species on the x axis; only the column names change.
