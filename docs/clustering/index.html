A Clustering Pipeline

Build a pipeline that groups records into segments (e.g., incidents by kind and severity, or sites by species composition) with a simple k-means routine and interprets what each cluster means. A distinct kind of analysis: unsupervised segmentation.

  • Clustering groups records without predefined labels.
  • k-means alternates assignment and centroid updates until stable.
  • The algorithm finds structure, not meaning: we have to interpret the clusters.
  • Validate by asking whether clusters are stable and useful.

18.1 Generate the blobs

  • Import the tools this lesson needs. math and random come from the standard library; polars builds the table and altair plots it. We fix the seed so the synthetic blobs are identical on every run.
import math
import random
import altair as alt
import polars as pl
SEED = 20261108
  • Each incident has two numeric features: a kind_code (a numeric encoding of the incident kind) and a severity score. We make four true groups and scatter points around each group’s center with random.gauss, so the data has real structure for k-means to find.
GROUPS = {
    "storm":        {"code": 0, "severity": 3.0, "spread": 0.5, "n": 60},
    "power-outage": {"code": 1, "severity": 4.5, "spread": 0.5, "n": 50},
    "flood":        {"code": 2, "severity": 6.5, "spread": 0.6, "n": 55},
    "fire":         {"code": 3, "severity": 8.5, "spread": 0.5, "n": 45},
}
def make_incidents(groups):
    random.seed(SEED)
    rows = []
    for kind, spec in groups.items():
        for _ in range(spec["n"]):
            rows.append({
                "kind": kind,
                "kind_code": round(spec["code"] + random.gauss(0.0, 0.15), 3),
                "severity": round(spec["severity"] + random.gauss(0.0, spec["spread"]), 3),
            })
    return pl.DataFrame(rows)
incidents = make_incidents(GROUPS)
print(incidents.head())
  • kind_code is a number because k-means works on distances, and distances need numbers. The text label stays alongside for interpretation later.
  • Plot the raw points to see the structure we are trying to recover. The color is severity, not cluster: we do not know the clusters yet.
chart = alt.Chart(incidents).mark_circle(opacity=0.6).encode(
    x=alt.X("kind_code:Q", title="kind (numeric code)"),
    y=alt.Y("severity:Q", title="severity"),
    color=alt.Color("severity:Q", scale=alt.Scale(scheme="viridis")),
    tooltip=["kind", "severity"],
).properties(width=500, height=300, title="Incidents before clustering")
chart.save("clusters-before.json")
  • Four loose blobs are visible. k-means will recover them from distance alone, with no labels, which is the whole point of clustering.

18.2 Implement k-means

  • A centroid is a point that represents a cluster; a cluster is the set of records closest to its centroid.
  • Distance is Euclidean: the straight-line distance in the feature space, from math.dist.
def distance(a, b):
    return math.dist(a, b)
  • Start by choosing k points as initial centroids. Random starting points are the usual choice; fixing the seed makes the start reproducible.
def initialize(points, k, seed=SEED):
    rng = random.Random(seed)
    idxs = rng.sample(range(len(points)), k)
    return [points[i] for i in idxs]
  • Assignment: each point joins the nearest centroid. Update: each centroid moves to the mean of its members. That alternation is where the name “k-means” comes from.
def assign(points, centroids):
    labels = []
    for p in points:
        dists = [distance(p, c) for c in centroids]
        labels.append(dists.index(min(dists)))
    return labels
def recenter(points, labels, k):
    centroids = []
    for j in range(k):
        members = [p for p, lab in zip(points, labels) if lab == j]
        if not members:
            centroids.append((0.0, 0.0))  # empty cluster: keep a placeholder
            continue
        dims = len(members[0])
        mean = tuple(
            sum(m[d] for m in members) / len(members) for d in range(dims)
        )
        centroids.append(mean)
    return centroids
  • Alternate the two steps until the assignment stops changing: that is convergence. We cap the loop in case it oscillates.
def kmeans(points, k, seed=SEED, max_iter=100):
    centroids = initialize(points, k, seed)
    labels = None
    for _ in range(max_iter):
        new_labels = assign(points, centroids)
        if new_labels == labels:
            break
        labels = new_labels
        centroids = recenter(points, labels, k)
    return labels, centroids
  • Turn the two feature columns into a list of points, run k-means with k equal to the number of groups we generated, and attach the result.
points = list(zip(incidents["kind_code"], incidents["severity"]))
K = 4
labels, centroids = kmeans(points, K)
incidents = incidents.with_columns(pl.Series("cluster", labels))
print(incidents.head())

18.3 Look at the clusters

  • Plot each point colored by its cluster. The colors are the structure k-means found; they are not yet meanings.
chart = alt.Chart(incidents).mark_circle(opacity=0.6).encode(
    x=alt.X("kind_code:Q", title="kind (numeric code)"),
    y=alt.Y("severity:Q", title="severity"),
    color=alt.Color("cluster:N"),
    tooltip=["kind", "severity", "cluster"],
).properties(width=500, height=300, title="Incidents clustered with k-means")
chart.save("clusters.json")
  • The four colors line up with the four blobs, so the algorithm found the structure we planted. It did not know the group labels; it worked from positions alone.

18.4 Interpret the clusters

  • k-means finds structure, not meaning. A cluster is a set of nearby records; what it stands for is our job to decide.
  • Summarize each cluster by the kinds it contains and its average severity.
for cluster in range(K):
    members = incidents.filter(pl.col("cluster") == cluster)
    counts = members["kind"].value_counts().sort("count", descending=True)
    top = counts.row(0, named=True)
    avg = members["severity"].mean()
    print(f"cluster {cluster}: {len(members)} records, "
          f"mostly {top['kind']} ({top['count']}), mean severity {avg:.1f}")
  • Each cluster has a dominant kind and a severity level, so we can read them as segments: one cluster is mild storms, another is severe fires, and so on. Those labels are the meaning we assign, not something the algorithm returned.
  • The ecology twin runs the same way: encode each site’s species composition into numbers, cluster the sites, then ask a field biologist whether the clusters match habitat types.

18.5 Validate

  • Validation asks two questions: is the grouping stable, and is it useful?
  • Stability first. A single random start is a gamble: if two starting centroids land in the same blob, the final split can come out wrong.
_, other = kmeans(points, K, seed=SEED + 1)
for a, b in zip(sorted(centroids), sorted(other)):
    print(f"{tuple(round(x, 2) for x in a)}  vs  {tuple(round(x, 2) for x in b)}")
  • The second run’s centroids land in different places, so it found a different grouping. One start is not enough to trust.
  • The standard fix is to try several random starts and keep the one whose members sit tightest around their centroids. That tightness is the within-cluster sum of squares.
def sum_squares(points, labels, centroids):
    total = 0.0
    for p, lab in zip(points, labels):
        c = centroids[lab]
        total += sum((p[d] - c[d]) ** 2 for d in range(len(p)))
    return total
  • Run several starts and keep the best by that score.
def kmeans_best(points, k, starts=8, start_seed=SEED):
    best_score, best_labels, best_centroids = None, None, None
    for s in range(starts):
        labels, centroids = kmeans(points, k, seed=start_seed + s)
        score = sum_squares(points, labels, centroids)
        if best_score is None or score < best_score:
            best_score, best_labels, best_centroids = score, labels, centroids
    return best_labels, best_centroids
  • With the best of eight starts, the answer is the same whichever eight starts we draw, so the grouping is stable after all.
_, best_a = kmeans_best(points, K)
_, best_b = kmeans_best(points, K, start_seed=SEED + 100)
for a, b in zip(sorted(best_a), sorted(best_b)):
    print(f"{tuple(round(x, 2) for x in a)}  vs  {tuple(round(x, 2) for x in b)}")
  • We compare sorted centroid positions, not label ids, because the numbering may permute between runs while the geometry stays the same.
  • Usefulness: ask what a cluster lets you do. The best-of-eight clusters map cleanly onto kinds, so a dispatcher gets segments worth treating differently. If two clusters would be handled the same way, they may as well be one.
