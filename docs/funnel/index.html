A Funnel Pipeline

Build a pipeline that traces records through an ordered sequence of stages and reports the drop-off at each one. For the disaster example the stages are reported → triaged → dispatched → resolved (the status field); for the ecology example they are surveyed → identified → vouchered → published. A distinct kind of analysis: funnel and conversion analysis.

  • A funnel orders stages and measures conversion between them.
  • Each stage is a filter; drop-off is the complement of conversion.
  • Funnels reveal where a process loses records.
  • Stage order changes the answer, so write the order down before you read the numbers.

Start with the tools and the fixed stage order.

  • A seed makes the pseudo-random sequence reproducible, so this lesson runs the same every time and the numbers below can be checked against the output.
  • Each incident has one status: the furthest stage it reached. To make later stages progressively fewer, walk each incident forward and let a fixed fraction fall off at each step.
  • Grouping by status and counting gives a histogram of final states, not a funnel. A funnel counts every record that reached a stage, and a record that reached a later stage also passed through the earlier ones.
  • Give each stage an integer position, then count how many records reached a stage by summing the final-status counts from that stage onward.
  • cum_sum(reverse=True) adds the counts from the last stage back to the first, so reached at reported is all incidents and reached at resolved is only the survivors.
  • Conversion is the share that moved from one stage to the next; drop-off is the share that did not. They add up to one.
  • The last stage has no next stage, so its conversion and drop-off are null.
  • Plot the funnel as bars ordered by stage, with the reached count labeled on each bar.
  • The funnel shows the biggest drop-off is between dispatch and resolution (about 40%), then between triage and dispatch (about a third), so those are the transitions worth investigating first.
  • The answer depends on stage order: “reached triaged” assumes every triaged, dispatched, or resolved incident passed through triage. If a record can skip a stage, or two stages are not strictly sequential, the cumulative count is wrong.
  • Check the result: the first stage’s reached equals the total incident count, and conversion + drop_off is 1 for every stage that has a next one.
