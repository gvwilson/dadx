4  Data Dictionaries and Provenance

Build the metadata layer of a pipeline: a data dictionary that records each field’s name, type, units, meaning, and allowed values, and a provenance log that records each step’s inputs and outputs.

  • Metadata (data about data) is data too.
  • A data dictionary is a contract between producer and consumer.
  • Provenance lets someone reconstruct how a result was derived.
  • Reproducibility is impossible without provenance.

4.1 The data dictionary

  • A data dictionary has one row per field, with columns for the name, type, units, meaning, and allowed values.
  • The incidents table is the running example; the dictionary below documents its eight fields.
  • The allowed values for a categorical field are the controlled vocabulary for that column: nothing else may appear.
  • Writing those vocabularies as constants means the dictionary and the validation code share one source of truth.
  • Store the dictionary as a list of dicts first; a list is easy to read and edit, and every other tool can import it.
  • A categorical field stores its allowed values as a list; a numeric field stores a description of its range; None means the field is not constrained.
  • Turn the list into a dataframe so the dictionary renders as a table and can be queried. This is the point of “metadata is data”: the dictionary is just another table.
  • Lists do not display well in a cell, so join them into a comma-separated string for display and keep the original list for validation.
  • Because the dictionary is a table, ordinary dataframe queries answer questions about the data without touching the data itself.

4.2 The dictionary is a contract

  • The producer promises to write values the dictionary allows; the consumer relies on that promise. The dictionary is the written contract both sides read.
  • Validation turns the contract from a promise into a check: walk the categorical fields and flag any value outside the controlled vocabulary.
  • A few hand-written rows stand in for the producer’s output. Two values break the contract on purpose: "Flood" is capitalized and "critical" is not a severity in the dictionary.
  • The two violations are the contract doing its job: without the dictionary, "Flood" and "critical" would silently become separate categories in every downstream summary.

4.3 Provenance

  • The dictionary records what each field means; provenance records where each result came from.
  • A provenance log is a sequence of records, one per transformation step, each naming the step, its inputs, its outputs, and when it ran.
  • Appending one small dict per step keeps the log simple and machine-readable.
  • Run a small pipeline over the incidents and log each step. The log is the audit trail that links the final summary back to the raw rows.
  • Write the log as JSON lines: one JSON object per line, easy to append and easy to read back with any tool.
  • Reading the log back as a dataframe closes the loop: the metadata layer is itself queryable data, so you can ask “what were the inputs to the summary?”
  • Without this log, a summary is a rumor: you cannot say how it was made or re-make it.
  • The dictionary says what the data means; the log says where it came from. Together they are the metadata layer that makes a pipeline reproducible.

4.4 The ecology twin

  • The observations table needs the same treatment; only the fields differ.
  • Units matter more here: mass_g is grams, length_mm is millimeters, and count is a number of individuals.
